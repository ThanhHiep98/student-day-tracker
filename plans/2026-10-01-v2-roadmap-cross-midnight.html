Plan: v2 roadmap + Slice 1 — Activities that cross midnight

2026-10-01 · source: requirement/Requirement.txt (new, alongside requirement/Requirement.docx) · summary: docs/REQUIREMENTS.md §4 · supersedes D5 of plans/2026-09-26-add-activity.html · related: docs/DECISIONS.md ADR-001 · Slice 1: implementer runs this next · Slices 2–8: plan later, one at a time

Scope

This file does two things. (1) It breaks Requirement.txt into eight ordered slices and surfaces two decisions the user must make (D-A auth, D-B goal categories). (2) It plans Slice 1 in full: logging an activity from 21:00 on one day to 01:00 the next. Slice 1 needs no decision, and later slices depend on it (sleep is the main habit the questionnaire asks about, and sleep crosses midnight). Not in Slice 1: onboarding, goals, warnings, ratings, stickers, accounts, overlap detection, and editing from History.

D-B · How do onboarding goals map to categories? Blocks slices 2, 4, 5

The requirement's example goals are school time, extra classes (học thêm), self-study (tự học), eating, entertainment, and sleep. Today's defaults are Work / Study / Exercise / Entertainment. Options: (i) add new default categories (Sleep, School, Extra class, Self-study, Meals) through an additive Dexie upgrade, and possibly retire “Work” for students; (ii) keep the defaults and let each goal question pick an existing or custom category; (iii) both: seed the new defaults and still allow remapping. Recommendation: (iii).

D5 override · cross-midnight (decided by the user; recorded here)

D5 in the shipped plan (“activities can't cross midnight”) is overridden by the new requirement. Two ways to store it:

ApproachForAgainst
Split into two per-day rows, linked by spanId (chosen)Every row stays on one IsoDate with minutes in a single day. The daily, weekly, and monthly helpers and the History lookups keep working unchanged, and each day gets the correct total (3h on day 1, 1h on day 2).Edit and delete must act on both rows in one transaction. Session counts must count a span once.
One row with endDate or endMinutes > 1440One row per activity.Breaks “minutes 0–1439 on one date”. Every aggregator would have to split the row by day, and the date index would miss it when querying day 2.

Slice 1 — Flow

Slice 1 — Data shape

  • Activity.spanId?: string. It is set on both rows of a cross-midnight activity and equals the head row's id. Same-day rows leave it unset. The tail row's id is `${headId}-next`, so the demo- prefix and “Clear & start fresh” keep working.
  • startMinutes stays in 0–1439. endMinutes is end-exclusive in 1–1440, and 1440 means “ends at midnight”. A span is at most 23h59m: the head row ends at 1440 and the tail row starts at 0.
  • Dexie adds .version(2).stores({ activities: 'id, date, categoryId, [date+categoryId], spanId' }). This only adds an index and needs no upgrade function. version(1) stays as it is.

Slice 1 — Success criteria

  • ☐ pnpm typecheck, pnpm check, pnpm test, pnpm build, pnpm test:e2e all pass.
  • ☐ Entering yesterday 21:00 → 01:00 saves with no error (the bug from Requirement.txt is fixed).
  • ☐ It is stored as 2 rows: {date: D, 1260–1440} and {date: D+1, 0–60}, with the same spanId (= head id).
  • ☐ Home today: 1h tracked, row reads “00:00–01:00 · from previous day”. History yesterday: 3h, row reads “21:00–00:00 · continues next day”.
  • ☐ Edit from either row prefills start date D, 21:00, 01:00. Changing it to a same-day time leaves exactly 1 row and no orphan tail row.
  • ☐ Delete from either row removes both rows, and they stay gone after reload.
  • ☐ 21:00 → 00:00 is stored as 1 row with endMinutes: 1440.
  • ☐ Start = end shows Start and end time can't be the same. inline, and the dialog stays open.
  • ☐ The duration preview shows “4h · ends next day” for 21:00 → 01:00.
  • ☐ Insights counts a span as one session (unit-tested in all three helpers).
  • ☐ db.ts has a new version(2) block. version(1) is unchanged, and the upgrade from v1 data is integration-tested.
  • ☐ Demo “Clear & start fresh” removes both rows of a demo span.
  • ☐ 0 axe violations on /, /history, /insights, and the open Add dialog.
  • ☐ docs/ARCHITECTURE.md Status no longer lists cross-midnight or changing the date as deferred.
